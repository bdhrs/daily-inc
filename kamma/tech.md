## Constraints
- Solo developer with limited time — favour small, focused changes over large refactors.
- **AGP 9 is unreachable on Flutter 3.47.2** (verified 2026-09-18 by building every
  combination, not by reading docs). Four independent blockers, any one fatal:
  the legacy DSL is deprecated at ERROR level so `.kts` build files will not
  compile; `android.newDsl=true` makes Flutter's own Gradle plugin throw
  `ApplicationExtensionImpl cannot be cast to AbstractAppExtension`; AGP's
  built-in Kotlin is 2.2.10, below Flutter's hard floor of 2.2.20 (true of AGP
  9.4.0 too, so no AGP version fixes it); and with KGP retained, third-party
  plugin modules fail JVM-target validation (Java 11 vs Kotlin 1.8). Nine
  dependencies still apply KGP, so built-in Kotlin is blocked regardless.
  Gradle 9.1.0 does build with AGP 8.11.1, but no AGP 8.x claims Gradle 9
  support — deliberately not adopted. Recheck when Flutter's Gradle plugin
  supports the new DSL; until then the build warnings are suppressed in the
  justfile, not fixed.

## Conventions
- Follow existing patterns in the codebase. Do not introduce new patterns without a clear reason.
- Seed/default data ships as a JSON asset in the store's own format so it can be regenerated by the app's own export, not hand-built in Dart.
- An untouched item (empty history) always targets its `startValue` however old its `startDate` is — the penalty branch in `calculateTodayValue` is undone by the start-anchored clamp. Baked-in start dates are therefore safe for increasing items, but not for decreasing ones (start > end clamps to `endValue`).
- `epochDays`/`dateFromEpochDays` (`graph_style_helpers.dart`) must stay UTC-anchored, not local-midnight, to avoid a timezone-dependent fractional-day offset. `GraphStyle.stepDirection` must stay `1.0` — `0.0` looks correct in isolation but drops the most recent day's bar entirely (no "next" point exists to bound its interval). Any change to either must be verified by rendering on device, not by reading `fl_chart` source alone.
- A view routine that can decline to exit must report that back to its callers.
  `TimerView._exitTimerDisplay` gained a Cancel path and callers like
  `_navigateToNextTask` set one-way guard flags (`_isNavigatingNext`) on the way
  in that nothing resets, so an early return leaves the control dead for the rest
  of the session. Before adding a "stay here" branch to any exit path, grep the
  callers for latch flags that only ever get set.
- `DailyThing.todayValue` (→ `IncrementCalculator.calculateTodayValue`) is the
  single authority for an item's current target. It is history-driven: base from
  the last entry before today, then increment, grace period, missed-day penalty,
  pause freeze and clamp. A second calendar-projection helper once existed for
  pre-filling backdated history rows and drifted wildly from it (an item past
  its ramp always projected its `endValue`); it has been deleted. Do not
  reintroduce a parallel target calculation — anything needing "the target" calls
  `todayValue`. Note the main list renders `displayValue`, which returns today's
  *actual* when an entry for today exists and falls through to `todayValue`
  otherwise, and formats per item type (minutes as `mm:ss`, reps as `12x`) while
  the history editor shows raw decimals.
